# Pin Memo

Pin notes and clickable todos above Claude Code's input. Notes and completion states return when you resume **the same session in the same folder**. [한국어](README_KR.md).

## Install

Verified using Claude Code 2.1.292 engine tests and declarations. The visual band targets terminal and Desktop; VS Code chat and headless sessions can use commands and persistence.

```sh
claude plugin marketplace add YeonwooSung/my-claude-code-mods
claude plugin install pin-memo@my-claude-code-mods
# Or load this checkout for one session:
claude --plugin-dir ./pin-memo
```

## Commands

```text
/pin Remember to run tests
/pin - [ ] Check deployment secrets
/pin - [x] Update docs
/pin toggle 2
/pin check 2
/pin uncheck 2
/pin edit 2 - [ ] Check production deployment
/pin remove 1
/pin list
/pin clear
/pin help
```

Plain `/pin` lists full notes. Use `/pin add <memo>` to add content starting with reserved command words. Editing without a checkbox marker converts a todo to a plain note. Multiline input is one memo; the band displays one abbreviated row and `/pin list` preserves full content. Notes do not enter model context automatically.

The teal rounded band shows note and completion counts. Completed todos remain visible, dimmed and struck through. Click a checkbox or focus the band with `ctrl+x tab`, then Tab/Enter. No digit shortcuts interfere with typing into the prompt. Collapse and scroll use the engine's controls. Surveys temporarily take priority over the band.

## Persistence and limits

The engine's plugin-owned `$.store` holds JSON documents under keys combining absolute cwd and session ID. A new session or `/clear` gets a separate list; resuming the old identity restores its notes. Different symlink spellings are distinct folder identities.

Changes are saved before being shown as successful. Failed writes preserve the previous state and show an error. Invalid saved documents block edits rather than being overwritten; explicit `/pin clear` resets the current document. There is no automatic expiry.

Up to 100 notes, each at most 2,000 Unicode code points. IDs are never reused after deletion. The engine limits the entire plugin store to 4 MiB. Concurrent editing of the same session by separate processes has no live synchronization or conflict guarantee.

## Development

```sh
npm test
CLAUDE_BIN=/path/to/claude-2.1.292 npm run test:adapters
CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1 /path/to/claude-2.1.292 plugin test pin-memo
/path/to/claude-2.1.292 plugin validate pin-memo
npm run typecheck
```

Typecheck requires matching local engine declarations in `.claude-plugin/types`. For this implementation the declarations generated by 2.1.292 for an existing mod were copied locally; these files are ignored. Core tests exercise commands, document validation, storage failure/races and Unicode width. Engine tests exercise render trees and checkbox presses on terminal/Desktop. Actual terminal/Desktop pixel captures have not been verified.

## Hook and source-review details

`command.run` answers only `/pin` with local memo operations and text. The mod does not invoke slash commands, run tools/programs or contact a network host. Startup registers `/pin`; lifecycle and `turn.start` refresh the local cwd/session identity and memo store. `ui.render` preserves the existing AbovePrompt UI and appends this memo band; buttons update only this mod's stored memo/check state after checking identity. No conversation, permission decision, settings or instruction files are rewritten. Keys are local document/identity identifiers and constructors initialize normal controller state; they are not installer credentials or evaluated code.
