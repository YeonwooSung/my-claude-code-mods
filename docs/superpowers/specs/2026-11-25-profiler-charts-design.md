# Agent Profiler 차트 설계 초안

상태: 2026-11-25 사용자가 계획에 따른 제품 코드 구현을 요청함. 구현·검증 결과는 별도 검증 기록을 참조한다.

## 목적과 첫 구현 범위

Claude Code 안에서 세션의 시간 분포와 느려진 턴을 빠르게 파악한다. 첫 구현은 `agent-profiler`에 한정한다. 이 범위는 앞선 분석과 엔진 검증을 바탕으로 한 제안이다.

기존 `/profile-pane`에 다음 세 가지를 표시한다.

1. 세션 전체의 model / tools / blocking subagents / engine 시간 구성.
2. 최근 최대 12개 메인 턴의 시간 구성. 막대 길이는 표시 중인 턴의 최대 시간에 비례한다.
3. 세션에서 느린 도구 호출 최대 5개. 도구 종류별 누적 순위가 아닌 개별 호출 순위다.

턴 라벨은 보관된 턴의 순서이며, 원래 세션의 절대 번호처럼 표시하지 않는다. `droppedTurns`가 있으면 누락된 과거 기록 수를 표시한다. 턴 ID와 프롬프트는 차트 라벨로 사용하지 않는다.

## 접근 방식

| 접근 | 장점 | 비용과 제약 |
|---|---|---|
| 텍스트 차트만 사용 | 구현과 호환성 관리가 간단 | Desktop에서 얻는 시각적 개선이 작음 |
| 터미널 Raster + Desktop/VS Code SVG | 실행 환경에 맞는 차트 제공 | 두 렌더러와 실제 화면 검증 필요 |
| 외부 대시보드 | 확대·탐색과 복잡한 실행 타임라인에 유리 | 별도 실행·배포·접근 흐름 필요 |

제안: 두 번째 방식. 기존 텍스트 보고서와 같은 집계를 사용하고, 차트를 표시할 수 없는 환경에는 텍스트 요약을 제공한다. 외부 분석은 기존 OTLP/Jaeger 경로를 유지한다.

## 구조와 불변 조건

- `analyze.ts`의 기존 턴 집계 루프에서 턴별 내역을 만들고, 마지막 12개만 `Summary`에 추가한다. 턴마다 `summarize()`를 다시 호출하지 않는다.
- 기존 `attribute()`의 우선순위와 구간 계산을 사용한다. 백그라운드 에이전트 시간을 메인 턴의 추가 시간으로 합산하지 않는다.
- 전체 구성은 전체 세션 시간, 턴별 스케일은 표시 중인 최대 턴 시간, 느린 호출 스케일은 표시 중인 최대 호출 시간을 분모로 쓴다. 각 스케일을 명시한다.
- 두 렌더러는 같은 숫자 모델을 사용한다. 시간·단위·범례를 문자로도 표시하고 색상만으로 구분하지 않는다.
- 기존 `SummaryCache`의 profiler identity / version / live 500ms bucket과 갱신 제한을 유지한다. 새로운 상시 타이머를 추가하지 않는다.
- 렌더링 중 Git·파일 읽기·네트워크·store 쓰기를 실행하지 않는다.
- 각 mod를 단독 배포할 수 있는 구조를 유지한다. 첫 버전에서 다른 mod를 상대 import하거나 공용 패키지를 만들지 않는다.

## 렌더링 계약

- Terminal: `Raster` 셀을 사용한다. 한 셀 폭의 BMP 문자를 사용하며, 너비는 실제 패널 너비와 API 상한 512열 이내다.
- Desktop / VS Code: 정적 `Svg`를 사용한다. 첫 버전은 `isInteractive`, 스크립트, 외부 리소스를 사용하지 않는다. SVG 하나의 길이는 131072자 이하다.
- 패널 너비가 40열 미만, 본문 높이가 8행 미만, 또는 필요한 요소가 없으면 기존 텍스트 표시로 돌아간다.
- 정상 너비에서도 본문 높이에 맞춰 턴 표시 개수를 줄인다. 세부 목록은 스크롤 가능하게 유지하며 차트가 패널을 전부 차지하지 않도록 한다.
- 데이터가 없으면 `No turns recorded yet.`를 표시한다. 0ms는 빈 막대와 0ms로 표시하며 NaN·Infinity를 만들지 않는다.
- 음수·비유한 값은 그리기용 모델에서 안전하게 정규화한다. 원본 분석 레코드를 변경하지 않는다.
- 느린 호출의 라벨과 대체 텍스트는 기존 redactor 적용 후 길이를 제한하고 XML 특수문자를 이스케이프한다. Unicode 문자를 중간에서 자르지 않는다.
- 차트 생성 실패 시 기존 텍스트 표시로 돌아가며 도구·모델 처리를 방해하지 않는다.

## 정확성과 호환성

- model은 클라이언트가 관측한 응답 대기 시간이며 모델 내부 연산 시간이 아니다. engine은 잔여 시간으로 계산한 추정값이다.
- 느린 호출은 개별 호출의 경과 시간이다. 병렬 호출을 더하면 세션 시간보다 커질 수 있으므로 세션 구성비에 합산하지 않는다.
- 미완료 턴·호출은 running으로 표시하고, 종료 시각 대신 동일 캐시 시점의 now를 사용한다. 이를 위해 기존 slowest 결과에 running 여부를 추가한다.
- `/profile`, `/profile turn`, 상태줄, OTLP의 의미와 저장 형식을 유지한다. 새로운 데이터 수집이나 네트워크 전송을 추가하지 않는다.
- 대상 엔진은 2.1.302와 2.1.329다. VS Code 실표시에는 확장 2.1.299 이상이 필요하며, 엔진 테스트 통과만으로 실표시를 보장하지 않는다.

## 완료 조건

집계 일치, 두 렌더러, 빈 데이터·0값·미완료·기록 누락·리사이즈·세션 전환, 마스킹과 SVG 이스케이프를 자동 검증한다. 기존 20k span 성능 테스트를 유지한다. 실제 terminal / Desktop / VS Code 표시를 개별 기록하고 미실시 환경은 미검증으로 명시한다.

## 후속 후보

1. Context Inspector: 입력 토큰 추이, 압축 마커, 카테고리 구성. 입력 토큰과 컨텍스트 점유율은 서로 다른 지표로 표시한다.
2. Time Machine: 분기·편집·테스트 결과 타임라인. 큰 그래프의 생략과 선택 조작은 별도 설계한다.
3. Verify Board / Review Queue / Dependency Lens: 현재 상태를 집계한 막대부터 추가한다. 성공률 시계열과 의존성 그래프는 필요한 이력·연결 데이터를 정의한 뒤 구현한다.

후속 단계에서 실제로 재사용되는 계약을 확인한 후 공용화 여부를 판단한다.
