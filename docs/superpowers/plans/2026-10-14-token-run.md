# Token Run Implementation Plan

> Execute inline with superpowers:executing-plans. The user explicitly requested design, plan, TDD implementation and unit commits directly on main on 2026-10-14; no additional approval gate, branch or worktree.

**Goal:** A fully local runner playable during request failures or via `/token-run`.
**Architecture:** Pure fixed-step simulation and view, serialized best-score store, request observation, and a frame-clock Client in a dedicated Pane. AbovePrompt only offers entry after main-turn failure.
**Tech Stack:** TypeScript, engine JSX, existing Node test loader; no new dependencies.
**Spec:** ../specs/2026-10-14-token-run-design.md

## Global Constraints

- Node >=22.19.0; engine validation uses local Claude Code 2.1.292.
- Work on main, no branches/worktrees or push; preserve existing work.
- Fixed 64-cell world, 50 ms frames, minimum 24 columns/8 rows; score 0..999999.
- Preserve downstream events, stream chunks/results/errors and trees; no network/model/process calls.
- Survey wins; only main-turn errors invite; no invented OFFLINE status.
- Scores use plugin-owned store key token-run.best.v1 and schema {version:1,best:number}.

## Review Focus

1. Focus loss and narrow layout stop movement; resizing cannot create a collision.
2. Old Client messages after close/reset cannot write or reopen the current run.
3. Failed/delayed reads and concurrent writes cannot lower the best score.
4. Engine-only stream items do not falsely signal a recovered connection.
5. Modified keys never trigger game actions; timers do not multiply on redraw.
