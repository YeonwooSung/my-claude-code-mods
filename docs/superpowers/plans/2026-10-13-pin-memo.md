# Pin Memo Implementation Plan

> Execute inline with superpowers:executing-plans, using test-first cycles and unit commits. The user approved implementation and commits on 2026-10-13.

**Goal:** Persistent notes and clickable todos directly above Claude Code's composer.
**Spec:** ../specs/2026-10-13-pin-memo-design.md
**Architecture:** Pure immutable command model, a serialized storage controller, and an engine render adapter. Engine store keys isolate absolute cwd and session ID.
**Tech stack:** TypeScript, engine JSX, existing Node test loader; no new dependencies.

## Constraints

- Preserve existing work. Commit completed units and do not push.
- Use Node >=22.19.0 and Claude Code 2.1.292 for adapter validation.
- Maximum 100 notes, 2,000 Unicode code points per note; store limit is 4 MiB.
- Survey UI wins; preserve downstream trees/events/results; never call next twice.
- Read errors block mutations except explicit clear. Writes precede UI state changes.
- Simultaneous writers in separate processes are not synchronized.

## Review focus

1. Reserved command words as memo content must work through add.
2. A stale checkbox callback must not affect a new session.
3. A failed load must not overwrite saved notes with an empty list.
4. Narrow Unicode text must not mutate stored contents or overflow its row.
5. Rapid changes and failed writes must not poison the mutation queue.
