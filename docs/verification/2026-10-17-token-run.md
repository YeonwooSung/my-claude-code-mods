## Corrections and regression coverage

- Native Client focus makes parent Pane `isFocused` false. Removed the parent-focus gate from Client key handling and physics. The engine delivers Client keys to the focused Client. P explicitly pauses; the API offers no Client blur notification, so automatic pause on focus loss is not promised.
- Added track pointer subscription for native Client focus and left-click jump. Modified/right clicks and airborne extra jumps are ignored. README/help explain clicking the track or Jump and Escape's two-stage focus/close behavior.
- Dock/inline transitions remount the Client. The host now retains a bounded, cloned Game checkpoint in RAM before awaiting score storage; detach clears it. Interaction checkpoints retain pause/restart immediately; periodic running checkpoints can roll back about one simulated second. Remount resets native keyboard focus, requiring another click.
- Posted checkpoints include the highest local best, preserving it across restart/coalescing. Strict validation rejects malformed enums (including arrays), unsafe numbers, invalid obstacles and scores below checkpoint progress. Pure tests check cloning, malformed input and reachable seeded games across jumps, pauses, deaths and restarts.
- A rejected old asynchronous Pane open cannot detach a newer run. A held-open/close/reopen/reject regression verifies the newer game remains attached.
- The model-effort-band adapter assertion failed on engine-added ownership metadata. It now compares the intended downstream type/props/children exactly while allowing engine ownership metadata; production behavior is unchanged. This is committed separately as `a71ade7`.

Behavior fixes were preceded by observed failing regressions, then passed targeted and full suites. Independent read-only review found no remaining Critical/Important issues; its enum-coercion and smoke-refocus findings were addressed and verified.

## Limits

- Native GUI rendering in Desktop was not inspected. Desktop has engine Client mount/input/frame-clock coverage, which does not establish native GUI focus or pixel behavior.
- PTY assertions validate decoded terminal content and interactions, not a human pixel review in iTerm2.
- The failed request is a real connection refusal at a loopback endpoint, not a whole-machine network disconnection. The mod does not probe connectivity; server/auth/context failures may also offer the invitation.
- The initial extra native PTY run on 2.1.296 was blocked by an automatic approval-review usage limit. The subsequent additional-testing run completed successfully: 19/19 checkpoints, including record retention after process restart. Native terminal evidence now covers 2.1.296 solo and 2.1.301 solo/all seven mods.
- PATH's local 2.1.280 binary lacks the required API. All current engine/native evidence uses explicit compatible extension binaries. Initial CLI onboarding/installation may need a connection; the already-loaded game itself makes no network/model calls.
- Best records use local plugin storage without cross-process locking. Concurrent engine processes may race. Live game checkpoints are in memory only and are cleared when closing; only the best score survives process restart.


## Additional tests requested after the initial verification

Six behavior tests extend Token Run from 44 to 50 tests without changing production code:

1. A paused checkpoint restores while its score-store read is still blocked. The test deliberately holds the asynchronous storage boundary and releases it in finally.
2. Twelve consecutive Client remounts retain the same progressing run; close/reopen clears live progress while preserving the best score.
3. Malformed checkpoint enums, invalid numbers and a structurally valid game whose progress exceeds its posted score cannot save or poison a remounted Client.
4. Cancelling a streamed turn cleans up downstream and does not prefetch another chunk.
5. Twenty-four seeded courses each survive 24,000 frames (20 virtual minutes), totaling 576,000 frames / eight virtual hours. The driver uses legal jump actions and visible obstacles, without overwriting runner position, velocity or phase. Sampled checkpoints remain decodable and obstacle counts bounded through capped speed.
6. Score reaches 999999 at the boundary and remains capped as physics continues.

The first repeated-remount test draft tried advancing an already-unmounted drawing; the engine correctly rejected the test API call. The final test advances the active drawing and asserts visible progress and close/reopen behavior. This was a test setup error, not a product regression.

Mutation checks used disposable plugin copies under temporary directories. Each of these six deliberate bugs made the corresponding additional test fail: dropping checkpoint assignment, retaining the checkpoint after close, accepting invalid checkpoint messages, prefetching an extra stream chunk, reducing minimum obstacle spacing from 36 to 2, and removing the score cap. All temporary copies were removed. No production mutation was retained.

An exploratory removal of the explicit downstream iterator-return call did not fail: the engine also performs cancellation cleanup. This surviving mutation is not claimed as caught; the extra-prefetch mutation verifies the plugin's consumption boundary independently.
