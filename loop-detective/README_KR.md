# Loop Detective — 반복 실패 탐정

[English](README.md) | **한국어**

같은 Bash 명령에서 같은 실패가 반복되면 사건을 열어주는 Claude Code 모드입니다. 수정과 재시도 기록을 연결하고 다음에 확인할 만한 항목을 제안합니다. 도구 실행, 권한, 프롬프트, 파일에는 개입하지 않습니다.

## 설치

```text
/plugin marketplace add YeonwooSung/my-claude-code-mods
/plugin install loop-detective@my-claude-code-mods
```

개발 중에는 리포지토리 루트에서 실행합니다.

```sh
claude --plugin-dir ./loop-detective
```

Claude Code 2.1.287 이상은 모드가 기본 활성화됩니다. 이전 버전에는 `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1`이 필요합니다. 로컬 엔진 테스트는 2.1.280, 타입 검사는 리포지토리에 있는 2.1.292 선언을 사용합니다. 실제 대화형 UI와 여러 모드의 동시 사용은 별도의 통합 확인이 필요합니다.

## 명령어

| 명령어 | 기능 |
|---|---|
| `/loop-report` | 메인 에이전트의 진행 중인 사건, 근거, 다음 확인 항목 |
| `/loop-report --agents` | 서브에이전트 포함. 에이전트별로 독립 추적 |
| `/loop-report --history` | 종료된 사건 최대 100개 포함. `--agents`와 함께 사용 가능 |
| `/loop-pane` | 터미널·데스크톱의 실시간 사건 패널 |
| `/loop-reset` | 관찰 기록 초기화. 파일과 대화는 유지 |

상태줄 예시: `loop: 1 active · max 4 failures`. 새 사건마다 알림을 최대 한 번 표시합니다. 병렬 호출 결과를 처리하는 동안 이미 종료된 사건에는 알림을 띄우지 않습니다.

예를 들어 `npm test`가 세 번 동일하게 실패하고 호출 사이에 파일 수정이 성공했다면:

```text
Case #1 [edit-retry; active] — main
  3 identical failures · calls #1–#5 · 2 edit/retry transitions
  Command: npm test
  Cwd: /repo
  Failure: Error: expected 2, got 1
  Observed edited files (not causal evidence): /repo/a.ts
```

`retry`는 동일 실패의 재시도, `edit-retry`는 수정 후 동일 실패가 반복된 사건입니다. 후자는 테스트 기대값, 입력 데이터, 의존성 또는 다른 코드 경로를 살펴보도록 제안합니다. 수정된 파일이 원인이라고 단정하지 않습니다.

## 감지 기준

- 에이전트, 세션 작업 디렉터리, 정확한 명령 문자열의 해시로 묶습니다. 인자·따옴표·공백·디렉터리가 다르면 별개입니다. 작업 디렉터리를 얻지 못하면 해당 호출은 추적하지 않습니다. 명령 안의 `cd`는 명령 문자열에 포함되며 실제 셸 디렉터리를 추론하지 않습니다.
- 기본적으로 같은 실패가 연속 3회면 사건을 엽니다. 그 사이 성공한 Edit/MultiEdit/Write/NotebookEdit가 포함된 전환이 2회 이상이면 `edit-retry`로 표시합니다. Bash 시작 전 완료된 수정만 계산합니다.
- 명시적인 엔진 오류, 0이 아닌 구조화된 종료 코드, Node TAP/Jest/Vitest/pytest/Cargo/Go의 양수 실패 요약을 근거로 삼습니다. 단순히 `error`를 출력했다고 실패로 판단하지 않습니다. 테스트 실패 요약은 셸 종료 코드 0보다 우선합니다.
- 65,536자 이하의 전체 출력을 비교합니다. ANSI 색상, CRLF와 인식 가능한 테스트 실행 시간만 정규화합니다. 단언 값, 실패 개수, 테스트 이름, 소스 위치는 유지하므로 실제 실패 내용이 달라지면 연속 횟수가 새로 시작됩니다.
- 같은 명령이 성공하면 `recovered`, 실패 내용이 바뀌면 `changed`, 거부·중단·시간 초과·백그라운드·잘린 출력·지원하지 않는 결과는 `unknown`으로 종료합니다. 너무 긴 출력이나 내용 없는 오류도 `unknown`입니다. 다른 명령의 성공으로 사건을 종료하지 않습니다.
- 병렬 호출은 호출 시작 순서대로 결과를 처리합니다. 해당 그룹의 활동 없이 이후 도구 호출이 200회가 되면 만료합니다. 보관 한도나 대기열 한도를 넘은 사건도 만료하며 늦게 도착한 결과로 되살리지 않습니다.

동일한 실패가 반복된다는 관찰이지, 진전이 없거나 무한 루프라는 증명은 아닙니다. 원인이나 모델의 사고 과정을 판단하지 않으며, 제안된 가설을 이미 확인했는지도 알 수 없습니다. 비교는 의미 분석이 아닌 문자열 기반이며 비암호학적 해시의 충돌 가능성이 있습니다.

## 설정

`/plugin` 설정 메뉴 또는 settings의 `pluginConfigs`에서 설정합니다.

| 키 | 기본값 | 의미 |
|---|---|---|
| `threshold` | `3` | 정수 3–10. 잘못된 값은 3 사용. 로드·초기화 시 적용 |
| `toastAlerts` | `true` | 새 사건 알림 |

## 보관과 한계

메모리에만 기록하고 파일 저장, 내보내기, 네트워크 요청, 추가 모델 호출은 하지 않습니다. 재로드·세션 재개·`/clear`·`/loop-reset`에서 초기화하며 이전 대화를 복원하지 않습니다.

최대 512개 그룹, 128개 에이전트 컨텍스트, 그룹당 진행 중 호출 16개, 종료 사건 100개, 에이전트당 최근 수정 기록 100개, 사건당 표시 파일 20개를 보관합니다. 명령·디렉터리·파일·에이전트 표시명·오류 발췌는 각각 최대 160자입니다. 흔한 비밀 값과 터미널 제어 문자를 제거한 다음 길이를 줄입니다. 원본 출력, 수정 본문, 사용자 프롬프트는 보관하지 않습니다. 마스킹은 최선의 처리이며 해시는 익명화를 보장하지 않습니다.

Bash나 외부 프로그램의 파일 수정, 다른 에이전트의 수정은 계산하지 않습니다. 허용된 실행 시간 정규화 외의 로그 변화는 감지를 놓치게 할 수 있습니다. 의미가 같은 다른 명령이나 다른 표현의 오류는 묶지 않습니다. VS Code 채팅·비대화형 환경에서는 패널 대신 텍스트 보고서를 사용합니다.

## 개발·검증

```sh
npm test
CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1 claude plugin test loop-detective
claude plugin validate loop-detective
npm run typecheck
```

Node 테스트는 엔진·계정 없이 핵심 로직을 검증합니다. 어댑터 테스트는 실제 엔진 테스트 도구로 결과 전달, 초기화, 수정 후 재시도, 보고서, 알림, UI 오류 격리를 확인합니다. 타입 검사는 다른 모드처럼 `loop-detective/.claude-plugin/types/claude-code/index.d.ts`의 엔진 선언이 필요합니다. 대상으로 삼는 엔진의 선언을 사용하세요.
